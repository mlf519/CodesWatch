# CodesWatch

> 基于 Spring Boot 3 + 大语言模型的自动化代码安全审计平台

GitHub: <https://github.com/mlf519/CodesWatch>

## 项目简介

CodesWatch 将**人工代码审计流程自动化**：系统按照安全工程师的审计思路，对上传的项目依次执行依赖分析、接口提取、高危操作识别三个阶段，并将每个待审计点拆解为子任务逐个交由大模型分析，最终汇总生成专业的安全审计报告。

系统的代码审计能力主要依靠大模型能力——**后续大模型越强，系统越强**。

<br />

## 系统特性

- **自动化审计流水线**：依赖扫描 → 接口扫描 → 高危操作扫描，三阶段任务编排，全程自动执行
- **子任务完整覆盖**：所有接口均独立新建子任务逐一扫描，保证扫描完整性
- **人工审计流程自动化**：模拟安全工程师"先看依赖、再看接口、最后审高危操作"的完整审计思路
- **提示词可配置**：支持按扫描阶段自定义系统提示词 / 分析提示词 / 前后缀提示词，支持按漏洞类型配置专属分析提示词
- **多模型可配置**：支持配置多个大模型配置，可指定默认模型，支持 DeepSeek 等思考模式（推理模型）的请求与解析
- **实时可视化**：SSE 实时推送任务进度与多轮对话日志，含大模型请求 / 回复 / 思考过程全记录
- **专业报告导出**：支持 Markdown / PDF 格式的审计报告导出
- **能力依靠大模型**：审计能力随大模型能力升级而提升

## 快速开始

### 环境要求

- JDK 17+
- MySQL 8.x
- Maven 3.6+

### 部署步骤

**步骤 1：初始化数据库**

```bash
mysql -u root -p < init.sql
```

**步骤 2：修改数据库连接**

编辑 `src/main/resources/application.yml` 中的数据库连接信息。

**步骤 3：构建并启动**

```bash
mvn clean package
java -jar target/codeswatch-1.0.0.jar
```

**步骤 4：初始化系统配置**

访问 `http://localhost:8080`，在 **模型配置** 页面填入大模型 API 配置（如 DeepSeek），在 **提示词配置** 页面按阶段配置提示词。

**步骤 5：创建项目并扫描**

新建项目（上传项目源码 ZIP 包），启动扫描。

## 功能使用介绍

### 1. 模型配置

在 **模型配置** 页面添加 / 编辑大模型配置：

- 填写配置名称、厂商类型（provider）、Base URL、API Key、模型名；
- 推理模型（如 DeepSeek-R1 系列）勾选 **支持思考模式**，系统将按思考模式构造请求并解析思考过程；
- 支持保存多个配置，通过 **设为默认** 指定扫描使用的模型，未启用 / 未配置提示词的阶段扫描时自动跳过。

### 2. 提示词配置

在 **提示词配置** 页面按扫描阶段配置提示词，系统内置默认提示词，可自由调整：

- **全局配置**：全局系统提示词、前缀 / 后缀提示词，拼接到所有分析请求中；
- **依赖扫描 / 接口扫描 / 高危操作扫描**：各阶段独立配置系统提示词与分析提示词；
- 接口扫描支持按漏洞类型（SQL 注入、文件上传等）配置专属分析提示词；
- 未配置的阶段不创建扫描任务，可按需裁剪扫描范围。

### 3. 创建扫描项目

在 **项目管理** 页面点击 **新建项目**：

- 填写项目名称、项目描述；
- 上传项目源码 ZIP 包（系统自动解压读取代码），保存后即可启动扫描。

### 4. 启动扫描与实时监控

- 扫描按 **依赖扫描 → 接口扫描 → 高危操作扫描** 三阶段自动执行，每个待审计点自动建立子任务逐项分析；
- 扫描过程通过 SSE 实时推送：任务进度、执行日志、多轮对话记录（含大模型请求 / 回复 / 思考过程）全程可视；
- 日志区支持自动刷新，手动滚动查看历史日志时不会被强制拉回最新。

### 5. 任务管理

- 单任务支持 **暂停 / 继续 / 重启 / 取消**，父任务支持 **全部暂停 / 全部继续** 批量操作；
- 任务失败或中断后可重启，从中断点恢复，不重复消耗 token。

### 6. 查看漏洞与导出报告

- 项目详情页汇总所有漏洞发现：等级（严重 / 高危 / 中危 / 低危 / 提示）、类型、位置、利用路径、修复建议；
- 扫描完成后自动生成审计报告，可在页面预览；
- 支持导出 **Markdown** 与 **PDF** 两种格式，PDF 带漏洞等级着色与专业排版，报告前置包含审计系统说明。

## 已知局限

- **大模型适配**：模型配置目前主要适配 DeepSeek，其他 OpenAI 兼容厂商未逐一验证；
- **框架适配**：接口扫描目前只适配了 `@GetMapping` / `@PostMapping` / `@RequestMapping` 类注解接口，其他框架（如 `@PutMapping`、JAX-RS、其他语言框架）暂不支持；
- **Token 消耗**：每个接口需按漏洞类型重复扫描，比较费 token；
- **漏扫风险**：单个接口分析中，多重 SQL 拼接或文件上传等多关注点的检查可能存在漏扫。

## 后续优化目标

- **适配更多大模型**：扩展更多厂商与本地模型的接入与验证；
- **适配更多框架接口**：支持更多 Spring 注解及其他框架 / 语言的接口提取；
- **研究 Code-Graph**：研究通过代码图（Code-Graph）等方式精确提供代码上下文，减少 token 消耗；
- **扫描调用栈**：研究单个任务建立栈结构，应对多重方法链路的深度扫描，减少漏扫。
